# 路线图与已知待办

这份只列**用户能感知的缺口**和**已知限制**，按「不做会不会出事」排序，不按工作量排。
已经做完的能力不在这里——它们按「需求 → 技术方案 → 实现功能」列在
[`docs/features/`](./features/README.md)。

编号（`S6b` / `L3` / `D5` …）是稳定标识，其他文档会引用它们，不要重排。
每条都写清「现在什么样」和「做完什么样」，有前置依赖的会标出来。

## 一、会话与数据

| 编号 | 缺口 | 现在什么样 | 做完是什么样 | 优先级 |
|---|---|---|---|---|
| `S6b` | 产物文件本身没进对象层 | 只记「哪些文件、改了几行、diff 是什么」，文件内容仍在宿主 `/workspace` | 文件按内容寻址存一份，会话跟着产物走；换机器或删宿主目录也能取回 | P1 |
| `S8` | 会话标题要解析压缩日志 | 日志是 zstd，不解首帧只有 id 和目录名，侧栏不好认 | 启动时解首帧拿标题（或复用 `session_projcache`），侧栏直接可读 | P1 |

## 二、容量与观测

| 编号 | 缺口 | 现在什么样 | 做完是什么样 | 优先级 |
|---|---|---|---|---|
| `C1` `C4` | 内存与卷配额没有指标 | 只有团队数、唤醒耗时；卷写满表现为 agent **直接停摆**（checkpoint fail-closed），不是变慢，且事前无告警 | per-team 内存 working set + 卷使用率，85% 预警 | P1 |

## 三、沙箱生命周期

| 编号 | 缺口 | 现在什么样 | 做完是什么样 | 优先级 |
|---|---|---|---|---|
| `L3` `L4` | 只有「停」和「删」两档，没有自动重建 | `compose stop` 与 `down` 混用；容器被外部删掉后只能报「需要完整重建」 | 「停」（释放内存、留容器）与「回收」（删容器、留卷）分档；对账发现容器缺失时自动拉起，会话从持久层拉回 | P1 |
| `L5` | 对象层只有本地目录后端 | 归档与会话正文都落在同一台机器的目录里 | `putFile`/`materialize`/`statObject` 三个函数换成 OSS，调用方不动 | P1 |
| `L6` | 归档包不含 workspace | 只打 `dsh-home` 卷，宿主 `workspace-team-X` 不在包里——**机器坏了没有产物副本** | 两个卷都进包，且走对象层而不是本机目录 | P1 |

## 四、Agent 能力

| 编号 | 缺口 | 现在什么样 | 做完是什么样 | 优先级 |
|---|---|---|---|---|
| `B1` `B2` | 「每天 / 定时」类需求不会真的建定时任务 | 实测两次：web 侧 agent 一次都没调 `schedule_create`，自己写脚本 + 让用户去配 crontab（容器里还没有）；headless 侧连 schedule 工具都没挂上 | web 用硬约束把「定时/每天/提醒」路由到 `schedule_create`，禁止 crontab/systemd/sleep 循环；headless 补齐 schedule 服务 | P1 |
| `A7` `A8` | 产物归因有两处盲区 | headless 会话默认没挂归因插件；非 git 工作区里由 MCP / shell 写入的文件归因为空 | headless 种子里也挂上；`/workspace` 默认 `git init`，快照走 git 就与「谁写的」无关 | P1/P2 |

## 六、IM 助理

| 编号 | 缺口 | 现在什么样 | 做完是什么样 | 优先级 |
|---|---|---|---|---|

## 明确不做的

不是「还没做」，是想清楚后**决定不做**，写在这里避免反复讨论：

| 项 | 为什么不做 |
|---|---|
| 一会话一沙箱 | 并发度约为 1，「团队 ≈ 一个对话」这个近似成立；照搬会让内存 ×N，单机预算装不下第 4 个并发会话 |
| 300ms 内存快照唤醒 | `stop`/`start` 实测 5.8s，配合反代等待页已经够用；内存态换出不值得这份复杂度 |
| 预热池 | 单机部署没有意义；K8s 下应该交给调度器 |
| 把消息级记录当恢复源 | 缺 tool result 和 request header，恢复不出来——正文必须是事件级 |
| 改 dsh 的持久化插件去写 OSS | 要实现完整的 handle/append/fsync/迁移语义，随 dsh 升级容易失配；sidecar 增量同步更稳 |
| 给会话压掉历史（compaction 减体积） | compaction 只隐藏 superseded entries，日志一条不删；指望它省空间是误解 |
