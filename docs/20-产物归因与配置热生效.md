# 20 · 产物归因与配置热生效

docs/16 说过会话日志「tool 级 checkpoint 够续跑」，docs/17/19 把 cwd 钉死在 `/workspace`。
但还有两个洞一直开着：

1. **「这一轮改了哪些文件」没有持久落点**。会话日志里的 `workspace/changes` 事件只带一个
   轮号，文件清单在 Host 内存、逐文件 diff 在 Session 私有临时目录，**Session 释放即删**。
   进程重启后，历史轮次连那张卡片都没有了。
2. **装一个连接器要重建容器**。`installMcp` 无条件返回 `restartRequired: true`，路由层接着
   `compose up --force-recreate`——40 秒，用户被踢下线。而实测 HMR 只要 2.11 秒。

这篇记这两件怎么改、边界在哪，以及为什么「热重载」必须带一个诚实的判定。

## 一、产物归因：两段式

### 为什么不能只靠会话日志

| 数据 | 在哪 | 会话释放后 | 进程重启后 |
|---|---|---|---|
| `workspace/changes` 事件 | 会话日志（卷 + 对象层） | 在 | 在 |
| 文件清单（`summary`） | Host 内存 Map | **没了** | 没了 |
| 逐文件 hunks（`diff`） | Session 临时目录 | **删了** | 没了 |

事件本身只写 `{turn}`，所以「第 7 轮改过东西」查得到，「改了什么」查不到。

### 采集：事件到达即抄

插件 `plugins/changes-collector/` 监听 `session/event`，遇到 `workspace/changes` 就立刻
`ctx.workspaceChanges.summary()` + 逐个 `diff()`，落成
`<DSH_HOME>/changes/<sessionId>/t<turn>.json`。

三个实现要点：

- **必须在事件里抄，不能在 dispose 时抄**。`workspace-changes` 自己的 dispose 会 `rm -rf`
  临时目录，两个插件的释放顺序没有约定，dispose 时抓是竞态。
- **以轮为文件名**。同一轮可能追加两条事件（轮内记录一次、`turn/end` 再补一次代表最终
  状态），按轮覆盖才是对的语义；按 seq 命名会留下两份互相矛盾的记录。
- **`summary()` 要重试**。`session.append()` 同步派发事件，而 recorder 是在 `append()`
  **返回之后**才 `records.set(event.seq, …)`——回调里直接取一定是 `undefined`。这里用
  25ms × 40 次轮询兜住。

体积兜底两级：超过 `maxBytes`（默认 1 MiB）先丢 hunks 保留清单（`detailOmitted: true`），
再超就截断到 50 个文件（`truncated: true`）。**清单永远保留**——用户最先要的是「改了哪些」。
本地目录按轮限 `maxTurns`（默认 200），兜住「控制面没在跑」时把卷写满。

### 上推：索引进库、详情进对象层

`deploy/orchestrator/artifacts.mjs` 的 `syncArtifacts` 做三件事，跟着会话同步一起跑
（5 分钟一轮，也可 `POST /sessions/sync` 手动触发）：

| 落点 | 内容 | 为什么 |
|---|---|---|
| `session_artifacts`（一行 = 一轮） | 文件清单 JSON、行数合计、对象键、digest | 要能 SQL 查「哪个会话动过这个文件」，且容器睡着也能查 |
| `objects/artifacts/<team>/<sid>/t<turn>-<digest>.json` | 完整记录（含 hunks） | hunks 动辄几百 KB，放库里涨到 GB 级；只在点开某一轮时读一次 |
| 卷里那份 | **收走即删** | 卷只当中转站。留一份等于「同一份数据两个真源」，早晚漂移 |

幂等靠对象键里的内容 digest：同一轮再同步时 digest 相同就只补索引、不产生第二个对象；
内容真变了才写新对象并删旧的。

### 查询

```
GET /sessions/:id/artifacts?team=team-a           → 轮级清单（最新在前，纯库查询）
GET /sessions/:id/artifacts/:turn?team=team-a     → 该轮完整记录（含 hunks，读对象层）
```

## 二、配置热生效：先热重载，失败才重启

### 现状不再「一律重建」

`restartDsh(team, mode)` 现在分两级：

| mode | 做什么 | 耗时（实测） | 用在哪 |
|---|---|---|---|
| `reload` | `docker restart`，容器不重建 | 5.2 秒到 healthy | 只改了 profile 配置（装/卸连接器、改 agent 参数） |
| `recreate` | `compose up --force-recreate` | 40 秒+ | 改 env（只在创建容器时注入）、换镜像、改挂载 |

`recreate` 那条注释里的教训仍然成立：**用 `restart` 顶替 `recreate` 会让 env 变更静默不生效**，
所以默认值保持 `recreate`，只有明确知道「这次只动了配置」时才传 `reload`。

### 装连接器：等热重载，等不到才降级

写 `cordis.patch.yml` 之后不再直接重建，而是 `waitPatchApplied()`（`deploy/orchestrator/reload.mjs`）：

| 判据 | 适用 | confirmed | 说明 |
|---|---|---|---|
| `process` | stdio 连接器 | `true` | 数 `/proc` 里命令行命中包名的进程：出现 = 加载了，消失 = 卸载了 |
| `hmr-window` | http/sse 连接器 | `false` | 等过 HMR 稳定窗口（`awaitWriteFinish` 2s + 重组，实测 2.11s），再用 `--dump-config` 确认那一行在合成树里 |
| 超时 | 都不满足 | — | 返回 `applied: false`，调用方 `restartDsh(team,'reload')` 兜底 |

**为什么不问 dsh 要工具清单**：那要走 Typert RPC（WebSocket），控制面没有客户端；`/proc` 是
本机就能读的事实。代价是依赖「命令行里有可识别的包名」，所以 `probeTokens` 只取长度 ≥10、
不以 `/` 或 `-` 开头的片段——`/workspace` 这种会和张三李四的进程撞上，误判比不判更糟。

返回值里 `restartRequired` 一律置 `false`（它的语义是「还需要重启吗」），实际做了什么在
`reload: { basis, confirmed, waitedMs, fallback? }` 里，门户据此决定要不要提示。

### HMR 的边界

`dsh-hmr` 明说：Headless、SDK、ACP 组合包在 YAML 里**禁用** HMR，只有启动器提供
`profileContext` 的 web 组合包开启。所以「热重载」这条路径只对 web 入口成立；
别的入口要么改 profile 让它也开 HMR，要么就接受重启。

## 四、两个必须记住的坑（都是「实例起不来」级别）

**1. `cordis.patch.yml` 的空集合只有一种合法写法：`[]`。**

卸掉最后一个连接器时，`replace(pattern, '\n')` 让文件只剩空白。dsh 要求这个文件是
「顶层 YAML 数组」，空白解析成 null，启动直接 fatal：

```
dsh: fatal uncaught exception: Error: dsh: patches /home/dsh/.dsh/cordis.patch.yml
     must be a top-level YAML array of loader patch entries
```

容器带 restart 策略，于是进入**重启循环**——用户看到的是整台实例挂掉。
真机踩到一次（21:01:57 卸 filesystem），只能挂卷把文件改成 `[]` 再重启。

修法是两层：`normalizePatchText` 把空内容写成 `[]`；`uninstallMcp` 补上装的时候一直有的
`validatePatch` 失败回滚。**装上要校验、卸下也要校验**，之前只有前者。

**2. `[]` 不能被当成普通文本追加。**

补上 `[]` 之后立刻踩第二个坑：`mergeMcpBlock` 把 `[]\n` 当非空内容，拼成

```yaml
[]

# >>> market:mcp:filesystem v1.2.0 …
- insert:
```

同一个 fatal。`mergeMcpBlock` 现在把 `^\[\s*\]$` 视为空。两条都有单测
（`make verify-market-patch`，19 条），因为靠真机试错太贵。

**3. 探针会数到自己。**

`countProbeProcesses` 是 `node -e <脚本>`，脚本源码里内联着 token，于是这个进程自己的
cmdline 就命中——永远 ≥1，「已加载」被无条件判真（实测 install 返回 `waitedMs: 62`，
而 HMR 至少要 2 秒）。现在脚本跳过 `process.pid`，并跳过同样形状的其它探针进程。

**4. 插件日志必须写 stderr。**

`dsh --profile headless --json` 把 JSONL 事件流写 stdout。`console.log` 一行
「已接管…」就让整条流不是 JSON，下游解析当场报 `Unexpected token 'c'`。
`changes-collector` / `workspace-guard` / `market-skill` 已全部改 `console.error`。

## 五、验证

| 脚本 | 条数 | 覆盖 |
|---|---|---|
| `make verify-artifacts` | 39 | 采集（含 summary 延迟、同轮覆盖、摘要缺失）、上推（对象 + 索引 + 收走即删）、幂等、内容变更换对象、坏数据保留重试、体积兜底、路径解析 |
| `make verify-reload` | 16 | 子进程出现/消失、超时如实报未生效、无子进程走配置树、探测线索过滤、探针排除自身、命令失败不谎报 |
| `make verify-market-patch` | 19 | 空内容 → `[]`、`[]` 追加、重复安装不叠块、升级替换、卸载回到 `[]`、多连接器只删指定那个（每条都过 YAML 解析） |

真机（team-a，`my-dsh:0.2.1-rc.5`）：

| 动作 | 结果 |
|---|---|
| 内置 `write`+`edit` 改文件一轮 | 卷里出现 `changes/<sid>/t1.json`：`attr-check/c.txt`、`action=created`、`added=2`、1 个 hunk |
| `POST /sessions/sync {team:team-a}` | `artifacts: {scanned:1, uploaded:1, failed:0}`；库 2 行、对象层 2 个、卷里剩 0 个文件 |
| `GET /sessions/<sid>/artifacts` | 轮级清单带 `files[]` 与 `detail.key`；`/artifacts/99` → 404 |
| `GET /sessions/<sid>/artifacts/<turn>` | 从对象层取回 hunks（`["+#!/usr/bin/env python3", …]`） |
| 卸 filesystem 连接器 | **2.45s** 返回，`basis=process, confirmed=true, waitedMs=2083`，`PID1` 不变（未重建），patch 归一成 `[]` |
| 装 filesystem 连接器 | **2.42s**，`waitedMs=2044`，MCP 子进程 21:06:31 起来（请求发出 21:06:28） |

对照改之前：同一条路径是 `compose up --force-recreate`，2026-11-08 19:38 那次实测
**重建 9 秒**（镜像已在本地），冷镜像时 40 秒+，且过程中 edge 返回 502。

## 六、还没做的

| 编号 | 缺口 | 影响 |
|---|---|---|
| S6b | 产物**文件本身**没有进对象层 | 现在归因记的是「哪些文件、改了几行、diff 是什么」，文件内容仍只在 `/workspace`（宿主 bind）。要「会话跟着产物走」得把文件按内容寻址存一份 |
| A7 | headless profile 没默认挂归因插件 | headless 跑的任务没有归因。web 是产品路径，headless 属自动化/调试，暂按现状（本次真机验证是手工在卷里给它加了 patch） |
| A8 | 非 git 工作区里 MCP / shell 的写入看不见 | `workspace-changes` 只认 dsh 自己的 `write`/`edit` 与 git 快照。实测用 `mcp__filesystem__write_file` 写文件那一轮，`workspace/changes` 事件根本没出现（不是我们抄漏，是上游没记）。根治办法是让 `/workspace` 成为 git 仓库——快照走 git 之后就与「谁写的」无关 |
