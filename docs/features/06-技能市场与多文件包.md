# 06 · 技能市场与多文件包

> 一句话：技能从「一段 prompt 正文」升级为「带脚本与 references 的多文件包」，按 digest 物化到容器，
> 表存元数据与授权、对象层/文件表存内容、容器存物化副本。
> 对应设计文档：[docs/11](../11-技能与连接器.md)、[docs/12](../12-数据模型.md)、
> [docs/13](../13-技能包与对象存储.md)

## 一、需求

| 原始问题 | 不做的后果 |
|---|---|
| 市场技能只有 `SKILL.md` 正文 | `scripts/`、`references/` 进不去，技能只能当 prompt 用，跑不了脚本 |
| `market_items.content` 是 SKILL.md 的第二份拷贝 | 与 `market_item_files` 天然漂移，两份事实 |
| 配置散在「一堆 JSON + 卷里的目录」 | 文件是事实、`packages.json` 是旁注，两套状态对不上 |
| 同名包被不同团队发布 | 没有名称归属判定，会被抢名 |
| 分享一个包给别的团队 | 直接生效等于把别人的凭据也带过去 |

## 二、技术方案

**选 SQLite 而不是 Postgres**：单机零运维、单文件可快照、事务与唯一约束齐全；换 PG 只需把
`AUTOINCREMENT` 改 `GENERATED ALWAYS AS IDENTITY`，其余 DDL 不动。

**三层职责**：

```
表（market_items / market_item_files / team_skills / shares） → 元数据、授权、文件清单
对象层（当前降级为文件表）                                    → 包内容
容器 $DSH_HOME/market-skills/<name>@<ver>-<digest:8>/         → 物化副本（可丢弃重建）
```

**D9 的核心改造（一次做完，不能分两步）**：`content` 列一旦删掉，所有读正文的路径
（`skillBodyForTeam` / `publishSkill` / `migrate-db.mjs`）就都断了。所以同一个提交里完成：
建/改 `market_item_files` → 把存量 `content` 搬进 `['SKILL.md']` 并补最小 frontmatter →
`ALTER TABLE ... DROP COLUMN content` → `digestOf` 改算「路径 + 内容 sha256 + exec 位」 → 重算全部 digest。

**打包确定性**：tar 的 mtime / uid / gid 置 0、按路径排序、只保留 exec 位，所以同一个包
每次打出来的 digest 一致 —— 这是「内容变了才重新物化」的前提。
自己解 tar 而不调 `tar` 命令：符号链接条目能指向包外让后续条目写穿过去，事前查名字挡不住；
只收 typeflag `0` 最干净。上传只收 `tar.gz` 不收 zip（zip 解析是几百行最易出越界问题的代码）。

**分发两档**：单 `SKILL.md` 的纯 prompt 技能走 `GET /market/skills/:n/:v` 文本接口；
带附件的走 `GET .../bundle` 返回 gzip + `X-Dsh-Digest` / `X-Dsh-Manifest` / `X-Dsh-Files`，
客户端解开后自己算一遍清单摘要，对不上就丢弃。

**物化**：`plugins/market-skill` 的 `get()` 分流 → 临时目录 + 原子 `rename` + `.dsh-market.json`
标记；`resourceBase` 从 `opaque` 变成 `{kind:'directory', path:...}`；启动异步预热 5 个、
同名留最近 2 个；`team-up.sh archive` 排除 `market-skills/`（它可重建，不该进归档包）。

**发布优先取团队卷里的真实目录**（手写的 `skills/<name>`，或用户改过的 `market-skills/<name>@*`），
都没有才从库里 fork —— 这样「在物化目录里改一行再 publish」能带上那行。

## 三、实现功能

| 功能点 | 入口 / 文件 | 关键行为 |
|---|---|---|
| 包元数据与文件表 | `init-db.sql: market_items / market_current / market_item_files / team_skills / shares / ops / market_tokens` | 一行一个版本；`market_current` 做发布指针；`UNIQUE(kind,name,version)` |
| 打包/解包 | `bundle.mjs`: `walkSkillDir / filesDigest / buildTarGz / readTarGz / safeEntryPath / fileManifest / stripFrontmatter` | 确定性 tar、`../`/绝对路径/符号链接/条目数超限全部拒绝 |
| 入库与迁移 | `db.mjs`: `digestOf / upsertItem / itemFiles / bundleInfoMap / itemBundleFiles / skillBundleForTeam / migrateItemContent()` | `openDb()` 里一次性迁移；整组替换文件（删掉的文件真消失） |
| 可见性与授权 | `db.mjs`: `visibleSkills / marketCatalog / marketRev / assertNameAvailable / mountSkill / setSkillEnabled` | 按 team token 过滤；本地同名技能遮蔽拦截 |
| 安装/卸载 | `market.mjs: installSkill / uninstallSkill`、路由 `POST /market/install`、`/market/uninstall` | 装完即用；`rev` 只随「装了哪个版本/开没开」变 |
| 发布与上传 | `publishSkill / publishSkillFromBundle / skillFilesFromTeam`、`POST /market/publish`、`POST /market/upload` | 上传 body 直接是 tar.gz，不走 multipart；返回 `from: 'volume' \| 'db'` |
| 分发接口 | `GET /market/skills`、`GET /market/skills/:n/:v`、`GET .../bundle` | 每项带 `bundle:{hasBundle,size,count,digest}`；`locator` 定锚版本 |
| 物化与预热 | `plugins/market-skill/index.js` | 异步预热、`resourceBase.path`、旧版本裁剪、exec 位保留 |
| 分享流水 | `shareAsset / shareSkill / shareMcp / enableShare`、`/market/share`、`/share/enable`、`/share/reject` | 投递到 inbox，接收方启用才生效；`stripShareSecrets()` 去掉凭据 |
| 操作审计 | `db.mjs: appendOp / opsForTeam`、`ops` 表 | 装/卸/发/分享留痕 |
| 门户 | `plugins/client-ui-market/` | 市场浏览、安装、已装列表 |
