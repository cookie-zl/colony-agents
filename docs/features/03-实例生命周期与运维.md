# 03 · 实例生命周期与运维

> 一句话：闲置就把 dsh 停掉，有人回来自动拉起；容器、卷、对象层三者分别回收，状态永远以容器为准。
> 对应设计文档：[docs/09](../09-休眠与唤醒.md)、[docs/10](../10-平台运维.md)、
> [docs/14](../14-对象层.md)、[docs/16](../16-数据存放与重启存活.md)

## 一、需求

| 原始问题 | 不做的后果 |
|---|---|
| 团队多起来内存不够 | 一个团队的 agent 跑满编译，把整机 7 GB 预算吃穿 |
| 三份状态（注册表 / state.json / 真实容器）一定会漂移 | 门户显示「运行中」，实际容器早被手工删了 |
| 归档包只留在控制面本机磁盘 | 机器坏了没有副本 |
| 清理快照时逐条 `unlink` + 逐条 `console.error` | 事件循环被按住几十秒，`/health` 45 秒不响应，连带 auth 探活失败 → 用户看到 502 |
| 等模型 / 等审批时 CPU < 2% | 长任务被误判闲置杀掉 |
| 想让某个团队「常驻不休眠」只能改文件 | 改错没有校验，且运营得开终端 |

## 二、技术方案

**四级状态机的本地映射**（对齐 WorkBuddy 云端，但不照搬全部）：

```
运行 → 休眠（compose stop，容器留着） → 归档（打 tar → 删容器删卷） → 恢复（对象层取回注入）
```

不照搬三条：300ms 内存快照唤醒（我们是 `stop/start`，实测 5~8 秒）、1 Session : 1 沙箱、
「数天即回收」的激进窗口 —— 一个团队多人共享，销毁影响的是全团队，窗口必须更保守。

**休眠四条判据，缺一不可**（`docs/09`）：CPU 低 + 无活跃 HTTP + 超过 `idleMs` +
会话日志最近没有写入（TODO A4 补的第四条，防止长任务被误杀）。

**睡前顺序是硬约束**：

```
会话增量同步（上传 → 校验摘要）→ agent 参数入库 → 才允许停实例
```

顺序反了就是静默丢数据（TODO L1 / S4 的落地）。

**对账以容器为准**：`reconcile()` 每 10 分钟跑一次，用 `docker` 真实状态纠正 `state.json`；
孤儿卷只报告不自动删，`make reclaim` 才回收（且被容器占用的自动跳过）。

**归档进对象层**：`archive` 打出的 tar 不再留在本机 `archives/` 就算完，`storeArchive()`
把 `key + digest + bytes` 记进库，上传失败**自动降级回本机文件**，不丢数据。

**快照清理修的是根因**：改成「10 分钟内只清一次、单次最多 20 个、失败聚合成一条」，
不是给 `/health` 加缓存或加超时守卫。

## 三、实现功能

| 功能点 | 入口 / 文件 | 关键行为 |
|---|---|---|
| 供给 / 休眠 / 唤醒 / 销毁 | `runtime.mjs: provision / sleepInstance / wakeInstance / downInstance` | Helm 走 scale/uninstall，本地走 `team-up.sh` |
| 归档与恢复 | `runtime.mjs: archiveInstance / storeArchive / restoreInstance` | tar → 对象层 → 库记 key/digest/bytes；恢复按 key 取回 |
| 对象层接口 | `objects.mjs`: `putFile / putBuffer / readObject / materialize / statObject / deleteObject` | 内容寻址、去重、降级 |
| 状态与注册表 | `store.mjs: loadState / saveStateSoon / registry / saveRegistry` | 合并写、原子替换 |
| 快照与限流清理 | `store.mjs: snapshot / pruneSnapshots / restoreSnapshot` | 每小时自动拍；清理 10 分钟一次、单次 ≤20 |
| 漂移对账 | `console.mjs: reconcile()`、`GET/POST /reconcile` | 缺失重建、state 纠正、孤儿卷只报告 |
| 休眠/唤醒/状态接口 | `POST /sleep`、`POST /wake`、`GET /wake-state`、`GET /state` | 门户与 CLI 共用 |
| 配额与节点预算 | `GET /nodes`、`store.mjs: loadNodes / saveNodes` | `memBudgetGB` 余量分配，单容器 `cpus 1.5 / mem 2g` |
| 团队策略 | `POST /policy`（`autoSleep` / `idleMs`，带范围校验） | TODO A3 已完成；门户控件未做 |
| 活跃 turn 判据 | `scanSessions()` + 日志 `find -mmin` | TODO A4 已完成；查不到按活跃处理 |
| 观测 | `GET /metrics` → `metrics.mjs: renderMetrics()` | Prometheus 文本；`buildMetrics()` 带几秒缓存避免 docker stats 打穿 |
| 门户与 CLI | `make state / nodes / metrics / reconcile / archive / restore / snapshot / backups` | 运维不需要开终端敲 curl |

**验证证据**

- `verify-objects`、`verify-sessions`、`verify-shadow` 全绿
- `pruneSnapshots` 修复后：启动到 `/health` 200 从「卡死几十秒」变成 **4 ms**
- `docs/09` 实测休眠唤醒 5~8 秒，会话、工作区、登录态全部保留
