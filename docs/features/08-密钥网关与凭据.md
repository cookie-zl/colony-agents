# 08 · 密钥网关与凭据

> 一句话：模型真 key 永不出控制面，容器里只有 `gl_` 开头的可吊销 token；请求由控制面代发。
> 对应设计文档：[docs/18](../18-密钥网关.md)、[docs/06](../06-访问控制.md)、[docs/07](../07-多团队账号.md)

## 一、需求

| 原始问题 | 不做的后果 |
|---|---|
| 原方案把 `team-secrets.json`（明文 JSON）通过 env 注入容器 | 同机 root 用 `docker inspect` / `/proc/1/environ` 就能拿到真 key |
| 「加密存起来」并没解决问题 | 只要真 key 进了容器，解密材料也得进容器，等于没加密 |
| 每个团队要能单独配自己的模型 key | 共用一把 key 时无法按团队限流、吊销、审计 |
| 流式响应（SSE）经过代理 | 中间层缓冲会把流式变成「等到全说完才一次性返回」 |
| 市场 token 是长期只读凭据 | 容器直连控制面 9700，token 泄露面大 |

## 二、技术方案

**架构**：容器里的 `DEEPSEEK_BASE_URL` 指向控制面网关、`DEEPSEEK_API_KEY` 放的是**网关 token**，
不是真密钥。网关收到请求 → 用 token 反查团队 → 从 `team_secrets` 解出真 key → 代发到上游 →
把响应（含 SSE）原样回流。真 key 只在控制面进程内存里存在。

**信封加密**：`secrets.mjs` 用 KEK（`secret.key`，权限 0600）做 AES-GCM，
`seal(plaintext, aad)` / `open(blob, aad)`，AAD 绑定 `team + scope + key`，
换团队/换用途都解不开；`safeEqual()` 做常量时间比较防时序侧信道。

**两条 token，职责分开**：

| token | 存在哪 | 权限 | 生命周期 |
|---|---|---|---|
| `gl_` 模型网关 token | `team_llm_tokens` | 只能调 `/llm/*` | 可吊销、可轮换 |
| 市场 token | `market_tokens` | 只读本团队已启用技能 | 每团队一枚，可吊销 |

**SSE 不缓冲**：`llm-gateway.mjs` 显式设置 `X-Accel-Buffering: no` 与 `Content-Type: text/event-stream`，
逐块 `write`，不做聚合。

**被否掉的选项**：改 `session-persistence` 写 OSS 插件（语义太重，随 dsh 升级易失配）、
把 key 塞进 dsh 自己的凭据库（仍在容器里）、K8s Secret（换了挂载点但真 key 依然进容器）。

## 三、实现功能

| 功能点 | 入口 / 文件 | 关键行为 |
|---|---|---|
| KEK 与信封加密 | `secrets.mjs: kek / seal / open / safeEqual` | AES-GCM + AAD 绑定，KEK 文件 0600 |
| 密钥 CRUD | `secrets.mjs: putSecret / getSecret / listSecrets / deleteSecret` | 按 `(team, scope, key)` 定址 |
| 密钥表 | `init-db.sql: team_secrets`、`team_llm_tokens` | 密文入库，不存明文 |
| 网关路由 | `llm-gateway.mjs: parseGatewayPath / handleLlmGateway`、`/llm/*` | 只放行 `/v1/*` 路径，其余 400 |
| 团队级配 key | `POST /secrets`、`GET /secrets`、`make team-key` | 加密入库，不重启实例 |
| 网关 token 管理 | `GET/POST /llm-token` | 生成/吊销 `gl_` token |
| 容器侧接入 | `compose.yaml: DEEPSEEK_BASE_URL / DEEPSEEK_API_KEY` | 真 key 不出控制面；留空则直连官方（本地调试） |
| 市场只读 token | `GET /market/token`、`db.mjs` 的 `market_tokens` | 只能读本团队已启用技能，拿不到 console-token 的建/删团队权限 |
