# 04 · 会话存算分离与对象层

> 一句话：会话日志从「卷里唯一副本」变成「对象层权威 + 卷只是缓存」，此后销毁容器 = 清缓存而不是删数据。
> 对应设计文档：[docs/14](../14-对象层.md)、[docs/15](../15-会话存算分离.md)、
> [docs/16](../16-数据存放与重启存活.md)

## 一、需求

| 原始问题 | 不做的后果 |
|---|---|
| dsh 把会话写成 `sessions/<project>/<sid>/session.v4.jsonl.zstd`，且**只有卷里一份** | 平台不敢真删容器，任何清理策略都等于删数据 |
| 单条 tool result 可达 64 KB，50 轮就是几十 MB | 日志进事务库会迅速膨胀，备份不可用 |
| 每次全量重传日志 | 崩溃时丢最后一段，带宽也浪费 |
| 侧栏列表靠扫卷生成 | 卷丢了列表全丢，标题还得解析 zstd 首帧才知道 |
| 唤醒时 dsh 只认本地文件 | 表建得再全，起不来也白搭 |

## 二、技术方案

**不走「写一个 persistence 后端」**：那要实现完整 handle/append/fsync/迁移语义，随 dsh 升级容易失配。
改为 sidecar 增量同步（控制面），dsh 侧一个字节不改。

**三层分工**：

```
SQLite（team_sessions / session_sync）   → 索引与同步进度，一行一个会话
对象层 objects/<team>/...               → 日志分段、归档包、产物详情（大块、只追加、按内容校验）
卷 $DSH_HOME/sessions                    → 可丢的本地缓存，dsh 启动时从这里读
```

**区间对象而非整文件**：`session_sync.uploaded_bytes` 记录已推到哪个字节，下次只推
`[uploaded_bytes, size)` 这一段；分段阈值 `MIN_SEGMENT_BYTES = 256 KiB`，小于阈值的尾巴等
`IDLE_FORCE_MS = 10 min` 强制落一次。分段目录不参与对象键，反推出的键能精确删到对象。

**顺序固定**：上传 → 校验摘要 → 才允许本地清理。睡前强制同步是这条的落地（见 [03](./03-实例生命周期与运维.md)）。

**唤醒路径**：dsh 只有 jsonl 一个 provider，所以启动时必须「查库 → 拉对象 → 重建本地文件 → 起 dsh」。
`restoreTeam()` 就是干这个的，不能只把指针塞给 dsh。

**明确不做的**：不加 Redis（单控制面进程 + 每团队单容器，内存 LRU 够用）；不用消息级记录当恢复源
（缺 tool result 和 request header，恢复不出来）；compaction 不减体积（只隐藏 superseded 条目）。

## 三、实现功能

| 功能点 | 入口 / 文件 | 关键行为 |
|---|---|---|
| 会话索引表 | `init-db.sql: team_sessions` | 侧栏 `WHERE team_id=?` 直接出列表，不扫卷 |
| 同步进度表 | `init-db.sql: session_sync` | `uploaded_bytes` 增量位点 |
| 卷 IO 抽象 | `sessions.mjs: createVolumeIo / createLocalIo` | docker 卷与本地目录同一契约，自测不需要 docker |
| 分段与同步 | `listSegments / syncSession / syncTeam` | 解析 `find` 输出、按区间推、空闲强制 |
| 拉回重建 | `restoreSession / restoreTeam`、`POST /sessions/restore` | 按对象键 `materialize` 回卷 |
| 侧栏查询 | `listTeamSessions()`、`GET /sessions` | 带标题、cwd、项目、最后活跃时间 |
| 周期触发 | `POST /sessions/sync`、`scanSessions()` | 5 分钟扫描 + 睡前强制（见 [03](./03-实例生命周期与运维.md)） |
| 对象层五接口 | `objects.mjs`: `putFile / putBuffer / readObject / materialize / statObject` | 内容寻址 sha256、去重、取回一致 |
| 对象层辅助 | `objectPath / sha256File / objectExists / deleteObject / keyFromDiskPath / listObjectFiles` | 键解析、清理、枚举 |
| 归档包进对象层 | `runtime.mjs: storeArchive`、`docs/14` | 上传失败降级回本机文件，不丢数据 |
| 产物详情复用同一层 | `artifacts.mjs`（见 [05](./05-产物归因与工作目录.md)） | hunks 存 `objects/artifacts/<team>/<sid>/...` |

**验证证据**

- `make verify-sessions`：全部通过（含「侧栏能直接读到同步进度」「分片目录不参与对象键」「反推出的键真的能删到对象」）
- `make verify-objects`：全部通过（寻址/去重/取回一致 + 上传失败降级不丢数据）
- 真机 team-a 重建后会话仍在（对话能续聊、`--session-id` 能接上），日志 zstd JSONL 可用 `node:zlib.zstdDecompressSync` 直接解析
