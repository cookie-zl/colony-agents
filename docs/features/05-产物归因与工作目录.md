# 05 · 产物归因与工作目录

> 一句话：「这一轮改了哪些文件」有了持久落点；会话的工作目录钉在 `/workspace`，发版不丢。
> 对应设计文档：[docs/19](../19-工作目录固定与运行时环境.md)、[docs/20](../20-产物归因与配置热生效.md)

## 一、需求

| 原始问题 | 实测现象 |
|---|---|
| `workspace/changes` 事件的摘要在 Host 内存、逐文件 diff 在 Session 私有临时目录 | **Session 释放即删**，进程重启后历史轮次连那张卡片都没有 |
| 用户新建工作区时选了 `/home/dsh/测试1`（容器可写层） | 21:30 重建后目录条目数 = 0，脚本产物全丢，但**对话还在**（日志在命名卷里） |
| `/workspace` 只是 cwd 兜底，从没被登记成工作区 | 8 个会话堆进「未分组」：不能新建、不能改名、不能拖、没 hover 卡片 |
| 从「未分组」会话里点「新会话」 | `startSession` 回落到 `recent`（= 测试1），把用户从安全位置拉回可写层 |
| 镜像里没有 Python | `python: command not found`，退出码 127 |

**关键区分**：对话与产物不是一回事。会话日志在命名卷 `dsh-team-a_dsh-home`（`docker rm` 不动它），
产物在 cwd 目录（可写层，重建即蒸发）。「对话还在」不能推出「文件还在」。

## 二、技术方案

**两段式产物归因**（不是把 diff 直接塞进事务库）：

```
① 容器内采集：changes-collector 监听 session/event 的 workspace/changes
     → 事件到达即抄 → <DSH_HOME>/changes/<sid>/t<turn>.json（原子 rename）
② 控制面上推：syncArtifacts() 读卷 → 收进 session_artifacts 表 + 对象层 → 收走即删
```

索引在库、详情在对象层：`session_artifacts` 一行 = 一轮（`files` JSON、行数合计、
`detail_key`/`detail_digest`）；逐文件 hunks 进 `objects/artifacts/<team>/<sid>/t<turn>-<digest>.json`，
点开才读。幂等靠 `detail_digest` 判跳过；内容变了才写新对象并删旧对象。

**四个必须记住的坑**（都是实测踩出来的）：

1. `session.append()` 同步派发事件，但 recorder 在 `append()` **返回之后**才写 `records`。
   回调里直接 `summary()` 拿不到 → 必须 `setTimeout(0)` + 25ms×40 轮询。
2. 同一轮会追加两次事件（轮内 + `turn/end`）→ **以轮号命名**，按轮覆盖才代表最终状态。
3. 插件日志必须写 **stderr**：`dsh --json` 的 JSONL 在 stdout，`console.log` 一行就打挂下游解析。
4. `serializeRecord()` 体积兜底：超限先丢 hunks（标 `detailOmitted`），再截断到 50 个文件（标 `truncated`）。

**工作区收敛（按「不兼容旧数据、一切以当前版本为准」）**：根因是
`dsh-workspace` 的 `bootstrap()` 只在 `initialized === false` 时跑一次，11-04 建过第一个工作区后就永久跳过。
解法不是搬迁文件（`cp -a` + 校验），而是：

- `migrate-workspaces.mjs`：摘掉 `path` 不在 `/workspace` 下的登记、`sessionIds` 进归档、
  `initialized` 置 `false` → 交给 bootstrap 重建；幂等、可关（`DSH_MIGRATE_WORKSPACES=0`）、首次改动才备份
- `workspace-guard` 的 `ensureRoot()`：`create('/workspace','工作区')` 幂等兜底；`create` 对已存在
  path 不改 title，所以要把 bootstrap 生成的英文名 `workspace` 显式 `setTitle` 成中文（只改自动生成的名字）
- `forgetDir()` 只 `rmdir` **空**目录（非空目录会抛 `ENOTEMPTY`，天然保险，不用 `rm -rf`）
- `prepare-workspaces.mjs` 只补 `/workspace` 下的目录，且必须排在迁移**之后**

## 三、实现功能

| 功能点 | 入口 / 文件 | 关键行为 |
|---|---|---|
| 轮级采集插件 | `plugins/changes-collector/{package.json,cordis.patch.yml,index.js}` | `inject: ['workspaceChanges']`、原子落盘、`prune` 按轮保留 |
| 卷中转与解析 | `artifacts.mjs: parseChangeList / splitChangePath / dockerChangeStore / localChangeStore` | 三段式路径 `<sid>/t<turn>.json`；store 抽象便于无 docker 验证 |
| 上推与幂等 | `artifacts.mjs: syncArtifacts()` | 摘要比对 → 新对象 → 删旧对象 → 删卷里文件 |
| 查询接口 | `artifactsFor / artifactDetail`、`GET /sessions/:id/artifacts[/:turn]` | 列表带 `files[]` 与 `detail.key`；详情从对象层取 hunks；不存在 404 |
| 产物表 | `init-db.sql: session_artifacts`（`UNIQUE(team_id, session_id, turn)`） | 索引 + 倒序索引 |
| 新工作区钉到安全位置 | `plugins/workspace-guard/index.js` | 拦截 `registry.create()`，改写为 `/workspace/<name>` 并预建目录 |
| 根工作区登记 | `ensureRoot()` | 幂等 `create` + 自动名改中文 |
| 旧登记收敛 | `deploy/image/migrate-workspaces.mjs: planMigration / forgetDir` | 纯函数便于测；归档旧会话、清空目录 |
| 目录补建 | `deploy/image/prepare-workspaces.mjs` | 只补根内路径，索引缺失/损坏不阻止启动 |
| Python 运行时 | `Dockerfile:41-58`（见 [01](./01-平台基础与交付.md)） | `python3/pip/venv` + 别名 + `PYTHONUSERBASE` 进卷 |
| 归档排除缓存 | `team-up.sh archive` | tar 排除 `./market-skills`（见 [06](./06-技能市场与多文件包.md)） |
