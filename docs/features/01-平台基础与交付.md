# 01 · 平台基础与交付

> 一句话：本地跑的镜像和线上发版用的是同一份，配置分三层、插件随镜像走、入口脚本有严格的先后顺序。
> 对应设计文档：[docs/01](../01-本地运行.md)、[docs/02](../02-插件开发.md)、[docs/03](../03-社区插件.md)、
> [docs/04](../04-镜像与profile.md)、[docs/05](../05-Zadig交付.md)、[docs/19](../19-工作目录固定与运行时环境.md)

## 一、需求

| 原始问题 | 不做的后果 |
|---|---|
| 本机一套跑法、K8s 另一套，配置来源不同 | 「本地好的线上不对」，排查无从下手 |
| 用户在 UI 改了模型/preset，重启就被镜像基线覆盖 | 用户以为保存了，实际每次发版归零 |
| 插件靠手工往卷里塞 | 镜像升级后插件丢，或者各团队版本漂移 |
| 社区插件不锁版本 | 上游一发版，全平台行为跟着变 |
| 镜像里没有 Python | agent 写得出 `.py` 脚本，执行时报 `python: command not found`（退出码 127） |
| 入口脚本顺序随意 | 补目录与迁移互相打架，刚摘掉的旧工作区又被建回来 |

## 二、技术方案

**三层配置，后者覆盖前者**（`docs/04`）：

```
镜像基线 profile/（烘焙进 /opt/dsh-seed）
  → 数据卷 $DSH_HOME/profiles/web/cordis.patch.yml（用户层 / UI 改动）
    → 命令行 --patch（运行期覆盖，优先级最高，用于关市场、挂载开发插件）
```

关键决策：

- **seed 三态可控**：`DSH_PROFILE_SEED=refresh`（默认，每次启动重铺，线上与仓库永不脱钩）/
  `once`（只铺首次，本地留手装插件）/ `off`（完全自己管）。
- **refresh 与「UI 参数要保留」的矛盾**：refresh 会删掉 `cordis.patch.yml`，而 dsh 恰好把
  模型/preset/工具开关写在这个文件里。解法是 `profile-patch.mjs` 在铺之前 capture 用户现场、
  铺完按 `id` 叠回新基线，不是「别删」也不是「加个锁」。
- **插件随镜像分发**：构建阶段把 `plugins/` 打成 tgz 放进 `/opt/dsh/plugins-tgz/`，
  `plugins.txt` 锁版本；社区插件同样锁 spec，不做浮动版本。
- **入口顺序是硬约束**：`profile 铺放 → migrate-workspaces → prepare-workspaces → exec dsh`。
  迁移必须排在补目录之前，否则刚摘掉的旧路径会被补建回来。
- **启动器参数必须在 app 参数之前**：`dsh --profile web --patch X --host Y` 里，
  一旦出现 `--host`，后续全归 app 解析器，`--patch` 会判成 unknown option。
  且必须用 `--profile web`，不能用 `dsh web` 子命令（后者自带另一套选项表）。
- **交付**：Zadig 构建镜像 → 推公司仓库 → Helm 部署；K8s 侧固定单副本 + `Recreate`
  （一份 `$DSH_HOME` 卷只能被一个进程写，滚动更新会双写）。

## 三、实现功能

| 功能点 | 入口 / 文件 | 关键行为 |
|---|---|---|
| 单机起停与本地入口 | `Makefile: up / down / restart / reload / shell`、`deploy/compose/compose.yaml` | 一团队一个 compose project + Caddy + auth + dsh |
| 镜像构建 | `deploy/image/Dockerfile` | 两阶段：`pluginpack` 打插件 tgz，主镜像装 dsh/pnpm + 系统依赖 |
| Python 运行时预装 | `Dockerfile:41-58` | `python3 / pip3 / venv`、`python`+`pip` 别名、PEP 668 放开、`PYTHONUSERBASE` 进卷（装包跟着团队走、不污染别的团队） |
| profile seed 与参数合并 | `deploy/image/profile-patch.mjs`、`entrypoint.sh:20-27` | capture → refresh → merge，按 id 叠加 |
| 工作区迁移与补建 | `deploy/image/migrate-workspaces.mjs`、`prepare-workspaces.mjs` | 见 [05](./05-产物归因与工作目录.md)；两者顺序固定 |
| 插件开发/打包/安装 | `plugins/`、`Makefile: pack`、`docs/02` | 函数形态 `apply(ctx)`、`ctx.effect` 管资源、tgz 随镜像 |
| 社区插件锁版本 | `plugins.txt`、`docs/03` | 已装 `dsh-our-free-model`（免费模型车道） |
| 运行期覆盖层 | `entrypoint.sh:65-77` | `DSH_MARKETPLACE=off` 走最高优先级 patch；`DSH_EXTRA_PATCH` 挂开发源码 |
| CI 构建与部署 | `deploy/zadig/build.sh`、`deploy/helm/colony/` | `make helm-template` / `helm-lint` 本地校验 |
| 信号与进程管理 | `ENTRYPOINT ["/usr/bin/tini", "--", ...]` | dsh 自己 dispose 整棵树，compose `stop_grace_period: 30s` |
| 容器内常用排障 | `Makefile: token / ps / logs / verify` | 绕过登录的原始 token、profile 拼装校验 |

**验证证据**

- `make verify-profile` **30 条通过、0 失败**（agent 参数跨重启、cwd 补建、索引缺失/损坏不阻止启动）
- 真机 team-a 重建后：`python3 --version` 可用；`python` 别名生效；`github_daily_top_one.py` 类脚本能直接跑
- 容器 `/proc/1` 为 `tini`，重建后 `dsh --profile web --dump-config` 能拼出完整配置树
