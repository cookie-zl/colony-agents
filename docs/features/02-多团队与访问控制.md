# 02 · 多团队与访问控制

> 一句话：必须登录、必须属于该团队，才能看到那个团队的对话；一个团队 = 一套独立实例。
> 对应设计文档：[docs/06](../06-访问控制.md)、[docs/07](../07-多团队账号.md)、
> [docs/08](../08-动态建团队.md)、[docs/10](../10-平台运维.md)

## 一、需求

| 原始问题 | 不做的后果 |
|---|---|
| dsh 本身是**单用户**应用，没有账号体系 | 只要能连上端口就能看全部对话 |
| 多个团队共用一个实例 | 技能、连接器、模型 key、会话互相串 |
| 新建团队靠人跑命令 | 运营要开终端，且容易漏配端口/token/成员 |
| 统一登录与 dsh 自己的 token 是两套东西 | 登录通过了但 dsh 仍判 401，页面打得开、`/api` 全挂 |
| Caddy 转发丢端口 | 浏览器 Origin 与 dsh 收到的 Host 不一致，`directoryPicker/list` 等 `/api` 一律 403 |
| 出了事查不到人 | 平台层只能查「哪个团队在用」，查不到「谁说的」 |

## 二、技术方案

**一团队一实例**：每个团队一个 compose project（`dsh-<team>-*`），独立 Caddy 入口、auth 校验、
dsh 进程、`$DSH_HOME` 卷、`/workspace` bind mount。隔离粒度由进程与卷决定，不是靠应用层过滤。

**三层防线，顺序不能换**（`deploy/compose/Caddyfile`）：

```
① 没有 dsh-sso Cookie        → 302 去 /__auth/login?rd=<原路径>
② 有 Cookie 但不一定是成员   → forward_auth → auth:9000/__auth/verify（200 / 403）
③ 通过后才补 dsh 单用户 token → redirect 补 Cookie
```

**动态建团队**：控制面（9700）是「容器外的一层」，收到 `POST /teams` 后按节点配额挑端口
→ 调 `team-up.sh up <team> <port>` → 等 healthy → 把入口/成员写回 `accounts.json` → 同步 dsh token。
注册表**不能用 rename 写**（docs/08 踩过的坑：带安全删除钩子的文件系统上 rename 会触发钩子），
一律 `writeInPlace` 原子替换。

**配置与凭据分离**：`accounts.json` 是团队/成员的事实来源；`db.mjs` 里的 `users/teams/team_members`
三表目前仍是影子数据（TODO D10），切换前以文件为准。

**明确不做的**（记录在 `docs/ROADMAP.md` 的「明确不做的」）：一会话一沙箱（并发度约 1，内存 ×N 装不下）、
per-session token、拆 Caddy 路由、预热池。

## 三、实现功能

| 功能点 | 入口 / 文件 | 关键行为 |
|---|---|---|
| 统一登录与成员校验 | `deploy/auth/server.mjs` | `/__auth/login`、`logout`、`password`、`home`、`members`、`verify`；登录失败锁定 + 审计 |
| 三层反代 | `deploy/compose/Caddyfile` | `{http.request.hostport}` 原样带端口转发，`route` 强制顺序 |
| 动态建团队 | `POST /teams` → `runtime.mjs: provision()` → `team-up.sh up` | 自动分配端口、等健康、写注册表、同步 token |
| 团队列表与节点余量 | `GET /teams`、`GET /nodes` | 门户直接出列表与配额 |
| 活跃度上报 | `POST /touch` | 供休眠判据使用（见 [03](./03-实例生命周期与运维.md)） |
| 注册表原子写 | `store.mjs: registry() / saveRegistry()`、`writeInPlace()` | 临时文件 + 原子替换，失败不影响原文件 |
| 漂移对账 | `GET/POST /reconcile` → `console.mjs: reconcile()` | 缺失容器重建、多余报孤儿、`state` 以容器为准；孤儿卷只报告 |
| 审计流水 | `deploy/auth/audit/`、`server.mjs: audit()` | 登录、改密、访问留痕（按用户 id + 团队 + 路径去重） |
| 本地/云两种供给 | `runtime.mjs: provision()` | `node.provider === 'helm'` 走 Helm，否则走 compose |
| 排障入口 | `make token`、`make team-token` | 绕过登录的原始 token 链接 |
