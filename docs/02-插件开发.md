# 02 · 插件开发

dsh 的插件模型很小：**一个导出 `apply(ctx)` 的模块**。`ctx` 上挂着所有能力（工具、命令、事件、服务），你往里注册东西，插件卸载时框架自动回收。

## 三种形态，选最简单的

```js
// 1) 函数形态：绝大多数情况用这个
export const name = 'my-plugin'
export const inject = ['tools']
export function apply(ctx, config) { /* ... */ }

// 2) 对象形态：需要把 name/inject 和实现放一起时
export default { name: 'my-plugin', inject: ['tools'], apply(ctx) {} }

// 3) 类形态：插件要对外提供 Service 时
export default class MyService extends Service {
  static inject = ['tools']
  constructor(ctx) { super(ctx, 'myService') }
}
```

`inject` 是依赖声明：写了 `['tools']`，Cordis 会等工具注册表就绪再调用 `apply`，所以 `ctx.tools` 在 `apply` 里一定可用。

## 本仓库的目录约定

```
plugins/hello-dsh/
├── package.json        # dsh.bundle.patch 指向配置层；engines.dsh 声明兼容版本
├── cordis.patch.yml    # profile 引用这个包时插入哪些行
└── index.js            # 实现，导出 name + apply
```

复制即新建：

```bash
cp -r plugins/hello-dsh plugins/my-plugin
# 然后改三处：package.json 的 name/version、cordis.patch.yml 的 id/name、index.js
```

`name` 用团队 scope，如 `@colony/my-plugin`；`id` 是配置行标识，全 profile 内唯一。

## 开发循环

```bash
make reload       # 改完插件：重建镜像 + 替换容器，约 10 秒
make logs         # 看 [hello-dsh] plugin loaded 有没有打出来
```

**为什么不能像别的框架那样挂源码热重载**，这一点值得说清楚，否则你会自己踩一遍：

插件的 `import { defineTool } from '@deepseek-ai/dsh-tools'` 之所以能解析到 dsh 自带的那一份，靠的是 dsh 的 profile-resolution 拦截器——它只对**位于 profile 目录里**的模块生效（`$DSH_HOME/profiles/web/node_modules/...`）。把源码从宿主目录直接挂进来（`--patch` 指向 `/opt/dev/plugins/xxx/index.js`），实测直接失败：

```
hello-dsh-dev (file:///opt/dev/plugins/hello-dsh/index.js): failed to import:
Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@deepseek-ai/dsh-tools'
```

官方教程里 `--patch` 挂源码能跑，是因为那份插件待在 dsh 源码仓库里，普通 Node 祖先查找就能找到 `node_modules`。独立仓库没有这个条件。

所以本仓库的循环是「重新打包 + 重新安装」，好在代价很低：镜像里 `npm i -g dsh` 那层是缓存的，只有插件打包和 profile 安装重跑，实测改一行 JS 到服务可用约 10 秒。而且这条路径和你线上跑的路径**完全一致**，不会出现「本地好线上坏」。

想更快的话，唯一可靠的办法是让插件带上自己的 `node_modules` 并链接宿主包——但那会给插件塞进第二份 dsh 实例，和文档明确禁止的做法相反，不建议。

## 注册一个工具

```js
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'greet'
export const inject = ['tools']

export function apply(ctx) {
  ctx.tools.register(defineTool({
    name: 'greet',                                    // 模型看到的工具名
    description: 'Greet someone by name.',
    parameters: {
      name: { type: 'string', required: true, description: '要打招呼的对象' },
    },
    output: {
      schema: { type: 'string' },                     // 规范返回值类型
      render: (_args, value) => [{ type: 'text', text: value }],  // 转成模型可见内容
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
  }))
}
```

三段各有职责：`parameters` 用来给 `args` 做推导与校验，`execute` 返回 `output.schema` 声明的规范值，`render` 把规范值变成模型读到的内容。

## 让插件可配置

配置写在 profile 的同名行里，`apply` 的第二个参数拿到：

```yaml
# profile/cordis.patch.yml
- id: hello-dsh
  config:
    greeting: '晚上好'
```

```js
export function apply(ctx, config) {
  const greeting = config?.greeting ?? '你好'
}
```

注意：patch 的 `config` 是**整块替换**，不是深合并。用 patch 覆盖某行时，这一行需要的每个键都要重新写全。

## 需要清理的资源用 ctx.effect

`ctx.tools.register`、`ctx.on(...)`、定时器由框架托管，卸载时自动清。自己打开的外部资源（socket、子进程）要显式交回去：

```js
ctx.effect(() => {
  const timer = setInterval(tick, 5000)
  return () => clearInterval(timer)   // 插件卸载时执行
})
```

## 打包与安装

```bash
cd plugins/my-plugin && npm pack
# → colony-my-plugin-0.1.0.tgz

docker compose -f deploy/compose/compose.yaml exec dsh \
  dsh plugin --profile web add /tmp/my-plugin-0.1.0.tgz
```

`dsh plugin add` 做两件事：在 profile 目录里执行 `pnpm add`，以及把这个包追加到 `dsh.profile.bundles`。两处必须一致，所以**不要手工改 `package.json` 的 bundles 数组**。

正式发布不走手工：把插件放进 `plugins/`，`make image` 会自动打包并装进镜像。

## 五个必踩的坑

| 坑 | 说明 |
| --- | --- |
| 把宿主包打进产物 | `@deepseek-ai/dsh-*` 必须写在 `peerDependencies`，不能进 `dependencies`，否则插件自带一份实例，和宿主注册表对不上。dsh 的 profile-resolution loader 会把宿主的实例路由给你。 |
| 忘了 `engines.dsh` | 没有它时，安装与启动会退化成检查 `@deepseek-ai/dsh*` 的 peer 范围。写上 `>=0.2.0 <0.3.0` 更可控。 |
| TS 类型对不上 | npm 上 `@deepseek-ai/dsh-tools` 只发到 `0.0.1-rc.1`，运行时是 `0.2.x`。所以样板用纯 JS + JSDoc。真要上 TS，只转译不检查（`tsdown`），别在 CI 里卡 `tsc --noEmit`。 |
| 原生依赖装不上 | pnpm 默认跳过安装脚本。带 `node-pty` / `koffi` 这类依赖的插件，要把包键写进 `profile/pnpm-workspace.yaml` 的 `allowBuilds`。 |
| 从前端插件猜后端行为 | 带 UI 的插件要声明 `dsh.client`，是另一套注入机制（`@deepseek-ai/dsh-client-ui-slots` 等），不在本样板范围内。先用纯后端工具把逻辑跑通。 |
