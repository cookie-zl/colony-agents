# 03 · 用社区插件

dsh 的插件就是普通 npm 包，没有专用注册中心。所以「用别人的插件」= 在 `plugins.txt` 里加一行的 npm spec。

## 两种来源

| 来源 | spec 写法 | 适用 |
| --- | --- | --- |
| npm | `some-dsh-plugin@1.2.3` | 有正式发布、版本语义清楚 |
| Git | `github:org/repo#<40位sha>` | 只发了源码，没发构建产物 |

Git 来源有两个额外成本，能避开就避开：

1. 拉下来的是源码不是产物，作者必须提供 `prepare` 脚本自己构建，否则装完没有 `lib/` 直接加载失败；
2. pnpm 默认拒绝执行 git 依赖的安装脚本，第一次 `add` 会失败，要按报错把包键写进 `profile/pnpm-workspace.yaml` 的 `allowBuilds`——**这等于允许该包在安装时以 dsh 身份执行代码**。

所以优先选 npm 上预构建好的包；`dsh` 官方文档也是这个建议。

## 社区市场（应用内浏览安装）

`plugins.txt` 里默认装了一个社区市场组合包：

```
dsh-plugin@2.2.7
```

它给 Web UI 增加一个「插件」入口，可以浏览/搜索/安装社区精选的插件，数据来自 `api.dsh-plugin.org`。运行期需要满足：

- 容器能出网访问 `api.dsh-plugin.org` 与 npm registry；
- 镜像里有 `curl`（本仓库的 Dockerfile 已装，这个市场包用 curl 而不是 node fetch 拉目录，代理行为更可控）。

### 生产要不要开

**这是本仓库最需要你和安全同学对齐的一件事。**

市场让任何能打开页面的人，在你的服务器上装任意代码——插件 `apply(ctx)` 跑在 dsh 主进程里，权限等于 dsh 本身，不在任何沙箱内。一个内部平台通常不希望这样。

三个档位，按公司实际选：

| 档位 | 配置 | 效果 |
| --- | --- | --- |
| 全开 | `DSH_MARKETPLACE=on`，`DSH_PROFILE_SEED=once` | 用户自助装插件并保留 |
| 只看不装（推荐默认） | `DSH_MARKETPLACE=off`，`DSH_PROFILE_SEED=refresh` | 市场不加载；所有插件由仓库声明，重启即还原 |
| 完全不装市场包 | 删掉 `plugins.txt` 里那行 | 镜像里连代码都没有 |

`DSH_MARKETPLACE=off` 的实现是启动时叠一个最高优先级的 `--patch` 层（`deploy/image/patch/marketplace-off.yml`），只禁用那一行，包仍留在 `node_modules` 里——改回 `on` 重启即可，不用重建镜像。

## 已装：dsh-our-free-model（免费模型车道）

`plugins.txt` 里装了 `dsh-our-free-model@2.1.0`。作用：往 dsh 里注册一批**不需要 API Key** 的模型，模型选择器里多出 `Our Free Model` 分组；上游是 OpenCode Zen 与 Kilo 的公共免费网关，插件直连、不经中转。

### 先看这个：包已停维护

npm 上三个版本（含 `latest` = 2.1.0）全部被作者标了 `deprecated`：

```
OFM Fish package retired, not included in dsh-fish 1.0.0, and no longer maintained.
Back up existing local data before any migration or removal.
```

作者指向的继任包 `dsh-fish` 目前只有 `0.0.1`，描述是 "name reserved; first release in development"，装不了。

结论：**这是当前唯一能用的版本，但它不会再有修复**。上游网关改了协议、或者 dsh 内核升到不兼容，只能自己改代码或换方案。把它当「可选加成」而不是「生产依赖」——默认模型留一条可回退的路（见下文「换回官方模型」）。

### 装法：只加一行，不要再写 patch

```diff
# plugins.txt
+ dsh-our-free-model@2.1.0
```

它在 `package.json` 里声明了 `dsh.bundle.patch`，`dsh plugin add` 会把包名追加进 `dsh.profile.bundles`，它自带的 patch 层随之生效。

**不要**再往 `profile/cordis.patch.yml` 里加 `insert: - id: our-free-model`。两处同时注册会直接报：

```
duplicate loader entry id: our-free-model
```

安装体积约 4.7 MB / 74 个文件，装完镜像多这一层；构建日志会打一条 `[WARN] deprecated`，属预期。

### 配置模型：改 `agent-default-model` 行

默认模型不是 `llm` 行上的字段，而是一个独立插件行 `agent-default-model`（内置默认是 `deepseek-official` / `deepseek-flash`，需要 `DEEPSEEK_API_KEY`）。改成免费车道：

```yaml
# profile/cordis.patch.yml
- id: agent-default-model
  config:
    provider: our-free-model
    model: kilo-auto/free
```

两个字段的含义：

- `provider`：插件注册的路由 id。`our-free-model` 是可用车道，`our-free-model-region` 是被地区策略隔离的那批。
- `model`：上游模型 id，不是包内的静态清单。可用值现查：`GET /api/our-free-model/summary` 的 `catalog[].id`，或 Web 界面「设置 → Our Free Model → 模型清单」。

`config` 是**整块替换**，只写 `model` 会把 `provider` 冲掉，两个必须一起给。

### 为什么不在 UI 里选

容器用 `DSH_PROFILE_SEED=refresh`：每次启动都用镜像里的 profile 覆盖数据卷。而 UI 切模型会写回 profile 目录的 `cordis.patch.yml`——下次重启就被冲掉。

所以在线上的稳定做法是**改仓库 + 重建镜像**；UI 里切只对当前进程有效，适合试模型。

### 模型可用性三种状态

插件启动后会按当前出口逐模型探测，`summary` 里每个模型带 `availability`：

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `available` | 实测可路由 | 出现在选择器 |
| `throttled` | 网关回「免费额度用尽」 | 仍列出但不可用，额度按上游周期恢复 |
| `region-blocked` | 上游按地区拒绝 | 归入 `our-free-model-region` 分组 |

上游 5xx、429、超时、断网**不算**对模型的否定，不会把它踢出清单——只有网关明确说「没有这个模型」才会移除。

### 这台机器上的实测（2026-11-01，容器内出口）

| 项 | 结果 |
| --- | --- |
| 模型总数 | 22（`available` 15 / `throttled` 6 / `region-blocked` 1） |
| 默认模型 `kilo-auto/free` | 可用，`bench` 1.2 s 首字 1.04 s，36 tokens |
| 工具调用 | 通过本地转发端口实测返回 `tool_calls`（`finish_reason: tool_calls`） |
| 公告 feed | 拉不到（`raw.githubusercontent.com` / `cdn.jsdelivr.net` 在容器内不可达），不影响模型车道 |
| 宿主 peer 依赖 | 全部满足：cordis 4.0.5、dsh-llm / dsh-commands / dsh-credentials 0.2.1-rc.5、schemastery 3.18.5 |

`throttled` 的那 6 个正是 README 主打的 `deepseek-v4.1-flash-free`、`glm-5.3-flash-free` 等——免费额度是按出口 IP 算的，**别指望它们一定在**。真要用前沿模型，就得配 Key 走官方车道。

### 换回官方模型

删掉 `profile/cordis.patch.yml` 里那段 `agent-default-model` 覆盖即可，会退回内置的 `deepseek-official` / `deepseek-flash`。此时 `.env` 里的 `DEEPSEEK_API_KEY` 就必须填了。

### 合规与风险（上线前要过的）

1. **数据去了哪**：请求直连 `opencode.ai` / `kilo.ai`。Kilo 免费池在上游模型卡里声明 **prompt 可能被记录用于改进服务**。公司内部代码、客户数据不要走免费车道。
2. **它自带免密账号渠道**：2.0 起打包了 CodeArts、CodeBuddy、WorkBuddy、Qoder、TRAE、Cline、Gemini 等 13 个渠道（登录、账号池、积分领取）。在公司的服务器上挂个人账号池，通常不符合内部合规，建议保持默认不用。
3. **它能自我升级**：设置页有一键升级，从 GitHub 下包、校验后替换自身代码。整合包/托管部署应把 bundle config 设成 `distribution: 'managed'` 关掉这条路径（插件 README 有说明），避免和应用升级互相踩。
4. **它注册了自己的 HTTP 路由**（`/api/our-free-model/*`）和可选的本机转发端口（默认关，只许绑回环）。路由复用了内核的信任围栏，但仍是新增攻击面。

## 锁版本是硬要求

```diff
- dsh-plugin@^2.2.7     # 不要
+ dsh-plugin@2.2.7      # 要
```

理由很直接：镜像要能被同一条 git commit 复现。浮动版本会让「昨天好好的、今天重新构建就挂」变成常态，而且你没法回答「线上到底跑的哪一版」。

`dsh plugin add` 会把实际装到的版本写进 `profile/package.json`，那份文件是**产物**不是输入，不要手改。

## 上新插件前的检查清单

一行 `plugins.txt` = 一次信任决策。加之前至少过一遍：

- [ ] 这个包声明了 `dsh.bundle` 吗？（没有就只是普通依赖，不会激活任何配置层）
- [ ] 它的 `engines.dsh` 覆盖当前 `DSH_VERSION` 吗？
- [ ] 它的 `dependencies` 里有没有自带 `@deepseek-ai/dsh-*`？（有的话会和宿主实例打架）
- [ ] 它有没有 postinstall / prepare 脚本？做了什么？
- [ ] 它需要什么额外网络出口、额外二进制、额外挂载？
- [ ] 版本锁到确切号了吗？来源是官方 org 还是个人号新注册？

## 内网 / 离线环境

公司网络出不去时，把依赖前移：

1. **registry 代理**：`NPM_REGISTRY` 指向公司 Nexus / Artifactory，由它代理上游。构建期一次性拉齐，运行期不需要出网。
2. **vendored tarball**：`npm pack` 后把 `.tgz` 放进仓库（或制品库），`plugins.txt` 里写成 `/opt/dsh/vendor/xxx.tgz`——需要 Dockerfile 里 COPY 进去。适合供应商只给包不给源的场景。
3. **关掉市场**：`DSH_MARKETPLACE=off`，否则页面上的「发现」会一直转圈失败。

已经装过的包都在 `profile/node_modules` 里随镜像走，运行时不需要 registry。
