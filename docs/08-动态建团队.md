# 08 · 动态建团队（点按钮 = 建容器）

| 项 | 内容 |
| --- | --- |
| 目的 | 用户在门户里新建团队，后台真的创建一套隔离实例，无需人工跑命令 |
| 形态 | 本地模拟云：宿主上的控制面 + 现有的 `team-up.sh` + 现有的 Caddy/账号服务 |
| 不动的部分 | dsh 镜像、`Caddyfile`、Helm Chart、`team-up.sh` 的创建逻辑 |

## 为什么必须有一层「容器外」的控制面

容器是 dsh 进程的宿主，dsh 里的插件管不了自己的宿主——这是时序问题，不是权限问题。
所以「建团队 = 建容器」这个动作，只能由一个 **在容器外、持有容器权限的进程** 执行。

```
浏览器 ──▶ 团队实例的 Caddy ──▶ auth 服务（容器内）
                                   │  POST /teams（带 X-Console-Token）
                                   ▼
                            host.docker.internal:9700
                                   │
                            console.mjs（宿主进程）
                                   │  复用 deploy/compose/team-up.sh up <team> <port>
                                   ▼
                        新团队：dsh + auth + edge 三个容器 + 两个卷
```

本地是宿主上的 node 进程；云上是同一个接口，只把 `provision()` 换成 `helm upgrade --install`。

## 涉及的文件

| 文件 | 作用 |
| --- | --- |
| `deploy/orchestrator/console.mjs` | 控制面：分配端口、写注册表、调 `team-up.sh`、等健康检查、失败回滚 |
| `deploy/orchestrator/console-token` | 控制面鉴权 token（首次由 `team-up.sh` 自动生成，已在 `.gitignore`） |
| `deploy/auth/server.mjs` | 新增 `POST /__auth/teams`（仅 owner）、`GET /__auth/health`；门户页加表单 |
| `deploy/compose/compose.yaml` | auth 增加 `ORCHESTRATOR_URL`、token 挂载、`host.docker.internal` |
| `deploy/compose/team-up.sh` | `ensure_secret` 顺带生成控制面 token |
| `Makefile` | `make console` 起控制面 |

## 怎么用

```bash
export PATH=$HOME/.orbstack/bin:$PATH
make up            # 起 team-a（如果还没起）
make console       # 起控制面，保持这个终端开着
```

然后打开 `http://team-a.localhost:8080/__auth/home`，用 `alice / dsh-demo-1234` 登录，
页面底部会出现「新建团队」——填标识（如 `team-c`）、显示名、描述，点「创建并进入」。

大约 10~30 秒后，浏览器会自动落到新团队的 dsh 界面。中间发生了：

1. auth 服务把请求转给控制面（带 token）；
2. 控制面在注册表里登记团队，并把创建者加成成员；
3. 控制面调 `team-up.sh up team-c <端口>`，起三个容器 + 两个卷；
4. 抓到 dsh 的 token 并同步给账号服务；
5. 轮询新实例的 `/__auth/health` 直到 200；
6. auth 用**已有的跨 host 一次性票据**把用户送过去，自动换 dsh Cookie，直接进 UI。

端口从 8082 起自动分配，跳过注册表里已登记的、以及本机已被占用的。

## 踩到的坑：注册表不能用 rename 写

`accounts.json` 是以 **单文件 bind mount** 挂进每个 auth 容器的。用 `rename` 覆盖会换掉 inode，
已运行容器里的挂载点立刻悬空（`stat ENOENT`），账号服务当场退出——第一次实跑就是这样
拿到 502 的，控制面却显示创建成功。

所以 `saveRegistry()` 改为「写临时文件 → `copyFileSync` 原地覆盖 → 删临时文件」，保持 inode 不变；
同时 auth 的 `accounts()` 在读失败时沿用上一份缓存，避免读到半个文件就崩。

## 云上怎么换（同一个接口）

| 环节 | 本地 | 云上 |
| --- | --- | --- |
| 执行者 | 宿主 node 进程 | 独立控制面服务（或 K8s 里的 operator） |
| 创建动作 | `team-up.sh up` | `helm upgrade --install dsh-<id>` 或 K8s API |
| 端口 | 宿主 8082+ | 不需要，Service/Ingress 代替 |
| 健康检查 | `GET /__auth/health` | 同样的探针，改成 Service 地址 |
| 注册表 | `accounts.json` | PostgreSQL（`team` / `team_member` / `sandbox`） |
| 鉴权 | `X-Console-Token` | RBAC + 调用方身份 |

接口契约（`POST /teams {id,name,desc,owner}` → `{team:{id,url}}`）不变，所以 auth、Caddy、
镜像、Chart 都不用改。

## 现在这套东西的边界（别当成生产）

| 缺什么 | 后果 |
| --- | --- |
| 没有配额与限流 | 谁都能一直建团队，直到磁盘满 |
| 没有审批流 | owner 一点就建，没有二级确认 |
| ~~没有休眠/归档~~ 休眠已做 | 闲置即停 dsh（省 240MB/团队），见 [docs/09-休眠与唤醒.md](09-休眠与唤醒.md)；归档仍未做 |
| 没有对账 | 容器被手动删掉后，注册表里还留着一条点不开的记录 |
| 控制面是宿主进程 | 关掉终端就没了，门户按钮会返回「控制面未启动」 |
| 单机 | 多机需要把执行者换成调度器（见 `docs/07` 与方案文档第 14 章） |
